adsb-eval
append-only JSONL ログを用いた ADS-B 受信評価

現在の ADS-B 受信チューニングは、多くの場合、
readsb などのデコーダが提供する
瞬間的なスナップショット指標に基づいて評価されています。

これらの指標は観測しやすい一方で、
一時的な条件変動の影響を強く受け、
アンテナ、ゲイン設定、デコーダパラメータの変更を
客観的に比較する用途には適していません。

その結果、多くのチューニング判断は
再現性のない直感や断片的な観測結果、
経験則に依存して行われています。

adsb-eval は、この問題を
ADS-B 受信を「瞬間値」ではなく
「時間的に蓄積された統計問題」として扱うことで解決します。

受信データを append-only な JSONL ログとして長期間保存し、
単一の数値ではなく分布に基づいた証拠によって
受信品質を評価できるようにします。

--------------------------------------------------------
問題点

readsb が出力する stats.json は、
その時点の受信状態のみを表します。

監視用途としては有用ですが、
以下のような問いに答えることは困難です。

・アンテナ交換によって本当に受信性能は向上したのか
・ゲインを上げた結果、性能は改善したのか、
それともノイズが増えただけなのか
・設定変更による影響は時間を通してどのように変化するのか

履歴データが存在しないため、
チューニング判断の再現性や客観性を確保できません。

--------------------------------------------------------

アプローチ

ADS-B 受信に関する各種指標を
append-only な JSONL ファイルとして記録します。

この設計により、以下が可能になります。

・長期間にわたる受信データの蓄積
・電源断や異常終了時でも安全な動作
・事後的な統計解析と比較評価
・固定入力データを用いた再現実験

本プロジェクトの目的は可視化ではなく、
判断のための指標を提供することです。

主な特徴は以下の通りです。

・Web トリガに依存しない
・cron / systemd による定期実行を前提
・append-only ログと末尾修復
・公開を考慮した出力（位置情報のマスク対応）

--------------------------------------------------------

評価指標

受信品質は分布ベースの統計指標によって評価されます。

主な指標は以下です。

・avg
平均受信距離

・p50 / p90 / p95
遠距離受信性能を示すパーセンタイル指標

・max
観測された最大距離

・n_used
評価に使用されたサンプル数
信頼性の目安として使用されます

・n_total
観測された航空機の総数

・n_with_pos
有効な位置情報を持つ航空機数

・pos_rate
位置復号成功率

これらの指標により、
ばらつきや信頼性を考慮した判断が可能になります。

--------------------------------------------------------

実運用での結果

無指向性アンテナから高利得コーリニアアンテナへ
変更した際に、本手法を適用しました。

直感的には指向性の向上により
ゲインを下げるべきだと考えられましたが、
距離分布の解析により以下が判明しました。

・頭上方向の感度低下
・水平方向の受信範囲の大幅な改善
・高めのゲイン設定での全体的な受信バランスの向上

スナップショット指標ではなく
統計分布に基づいて調整を行った結果、
一日の捕捉機数は 200% 以上向上しました。

--------------------------------------------------------

出力ファイル

主な出力は以下の通りです。

・dist_1m.jsonl
時間区間ごとの距離分布

・dist_pos_health_1m.jsonl
距離ログから導出された位置復号健全性

・summary.json
最新の評価結果と集計情報

オプション出力（有効時）：

・adsb_perf_dist.jsonl
・adsb_perf_stats.jsonl
tar1090 由来の性能指標

すべての JSONL ファイルは append-only であり、
一度書き込まれたデータは変更されません。

--------------------------------------------------------

実行モデル

各スクリプトは cron や systemd timer による
定期実行を前提として設計されています。

一般的な実行構成は以下です。

・adsb_dist_logger.py
・dist_pos_health_logger.py
・make_summary.py

各スクリプトは独立して実行され、
一部が失敗しても他に影響を与えません。

自動チューニングやフィードバック制御は行いません。

--------------------------------------------------------

設計方針

・直感よりもデータに基づく判断
・信頼性のための append-only ログ
・予測可能な失敗挙動
・統計的信頼性の明示
・人間が判断することを前提とした設計

特定のデータベースや可視化ツールへの依存は避けています。
JSONL 出力は必要に応じて外部ツールで利用できます。

--------------------------------------------------------

設定思想

すべての設定は環境変数で明示的に与えられます。

以下は存在しません。

・設定ファイル
・YAML
・暗黙的なデフォルト

これにより、実行結果の再現性と比較可能性を確保します。

--------------------------------------------------------

ディレクトリ構成

src/
実行スクリプトおよび共通ライブラリ

tests/fixtures/
再現実験用の固定入力 JSON
git 管理対象

data/
実行時に生成されるデータのみ
git 管理対象外

--------------------------------------------------------

データの扱い

・JSONL ログは追記のみ
・サンプル数不足のレコードも保持
・summary は派生データとして再生成可能

評価信頼性が低い場合でもデータは破棄されず、
後からの再評価やフィルタリングが可能です。

--------------------------------------------------------

品質判定

各評価レコードには quality セクションが含まれます。

eval_ok = true
統計的要件を満たし、比較評価に使用可能

eval_ok = false
構造的には正しいが、評価には不適

主な理由：

・insufficient_samples
・位置情報不足
・起動直後などの過渡状態

評価不可レコードも意図的に保存されます。

想定利用パターン

・同一設定で長期間運用
・一度に変更するパラメータは一つのみ
・変更後も継続してログを取得
・期間ごとの分布を比較

複数の変更を同時に行うと比較の妥当性が失われます。

--------------------------------------------------------

非目標

本プロジェクトは以下を目的としません。

・自動最適化
・リアルタイム制御
・可視化ダッシュボード
・単一機体やパケット単位の評価

目的は自動化ではなく、評価です。
